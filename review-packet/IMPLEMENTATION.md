# Implementation and reconciliation

The existing `/board` meeting item opens a native dialog attached to its existing `task_id`. It displays allowed context, immutable versions, safe shared correction history and role-specific next actions. Status polls and focus checks perform reads only. The browser cannot select a principal, source, audience, provider or runtime capability. Existing middleware, meeting transport, executive code and artifact-review code are unchanged.

Migration022 is additive apart from wrapping the exact current meeting_queue function and adding revocation fences to its authority dependencies. The original queue body moves to a private function, loses web execution access, and remains the only implementation of canonical transitions. Generic complete/review/request_changes calls are refused for document-managed tasks; authorized document operations call the guarded existing transition with the exact version/hash. Other tasks still delegate unchanged. The migration refuses a different queue preimage or repeat installation. No seed, role creation, grants to the new RPCs, live configuration or business selection is included.

One document is unique on canonical task and request. It binds current request hash, task/item revisions, source revision, safe task projection, optional existing source-binding row hash, actors/audience epochs, curated evidence versions/classification, configuration hash and explicit decision reference. The current accepted meeting seam does not create a generic request_source_bindings row; absence is bound as absence, without manufacturing a second source history. Canonical lifecycle-only revision advances refresh the expected revision under the same transaction; content/authority changes fence old attempts and output.

Context/build/output/revise/handoff/review are independent explicit per-task rights. The required reviewer must retain both existing meeting review capability and explicit document review/output rights. All output audiences retain item/client access. Supplemental notes require current matching version/hash/classification, approved browseable content, current freshness and explicit use AND display release. Deep IP, training sources, use-only material, stale/withdrawn/foreign-client sources are refused. A builder audience, including Nat, cannot receive internal-financial content. Existing Nat full-transcript refusal is retained. Safe shared notes are deliberately not a channel for Rhys-private commentary.

Permission/classification/source changes increment a monotonic document authority epoch and preserve a hash-only authority journal. Revoke/regrant does not revive old output or permit an old revoked v1 to enter a new correction prompt. Reads, dispatch checkpoint, response recording and publication recheck the bound authority. Output bytes are read within the same locked SQL transaction; no public artifact storage or separate file-I/O race is introduced.

Selective A3 reuse: document prompt, strict response contract, exact source quotations, substantive revision rendering and the one-attempt no-tools/no-redirect/no-fallback HTTP transport from accepted A3 `e228b704aa9f2f872209f3b04d61314aef31f887`. New transport names isolate activation from old Workspace settings. At most two reservations per document, one per revision; configuration/timeout/prompt budget/output contract are explicit. Exact prompt hash and one-time dispatch checkpoint, raw response/hash, rendered version/hash and named initiator are retained. Automation executor is recorded separately. Lost responses, cancellation and restart never replenish budget. Only a recorded response under unchanged bindings can reconcile into a version without another provider invocation.

Two deliberate adaptations: versions live in private PostgreSQL with immutable triggers rather than a separate artifact root; and this candidate supports an actual human executor using drafting assistance. It does not pretend that Atlas is the canonical human executor or introduce an Atlas-executor bypass. If the actual human decision chooses canonical Atlas execution, that requires a further narrowly reviewed implementation. No real executor choice has been made. Document-specific audit/version records extend the task; they do not create another business task list.

Known operational limits: new authority triggers scan document bindings and take transactional locks. Small synthetic scenarios and concurrent build callers were tested; production-scale contention, concurrent operator revocation deadlocks, hosted rollout locks and throughput were not load-tested. A PostgreSQL serialization/deadlock failure must hold the action for reconciliation, never automatically repeat a provider dispatch. Revoked output is retained privately, but unavailable to the task panel pending operator review; there is deliberately no self-service reauthorization or budget-reset endpoint.

No standalone Workspace revival, automatic intake, Slack carrier integration, external delivery, financial declassification or generalized agent platform was added. Executive/Newie/calendar coverage, real device use, genuine usefulness and commercial acceptance remain separate existing gates.
